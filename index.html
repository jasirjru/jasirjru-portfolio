The system

FastAPI serves document-question-answering workflows to a Next.js/TypeScript interface. BGE-small embeddings in Qdrant and BM25 lexical retrieval are combined with reciprocal rank fusion. Retrieval is scoped to a user’s own documents.

The reliability work

Gemini, Groq and OpenRouter routing includes retries, circuit-breaker failover, response caching and per-user quotas. The project’s CI covers backend tests, migrations, linting and a TypeScript build.

A result that changed the story

On the recorded synthetic development benchmark, dense retrieval reached MRR 0.910; BM25 reached 0.810 and hybrid fusion 0.900. Adding another retrieval method did not improve the overall result.

What this does not establish

The corpus has only 50 synthetic passages. Ninety answerable queries were scored; ten unanswerable queries were excluded from these retrieval metrics. The same dataset was used during later tuning, so it is not an independent test of generalization or answer quality.

Timing, precisely

The 3.7 ms median wraps query embedding plus in-memory dense search on CPU, with the embedding model already loaded. It excludes model startup, HTTP/network time, reranking and LLM generation. Hardware was not recorded and the run was not repeated. Earlier 0.36 ms hybrid timing used cached embeddings and is not comparable.

Serving contracts

Single-record and batch FastAPI endpoints serve scikit-learn preprocessing and Random Forest scores. Batch requests are bounded at 100 records. Pydantic rejects unknown fields, invalid categories, non-finite values and inconsistent service combinations.

Artifact integrity

Startup checks SHA-256 hashes, estimator metadata and feature order against a versioned manifest. A mismatch prevents the service from starting. Integrity verification does not establish predictive quality.

Configured verification

GitHub Actions runs pytest, Playwright browser scenarios, Docker builds, vulnerability scanning and authenticated inference smoke checks. These are configured checks, not a claim that every current run passes.

Model limitations

The legacy serving scores are uncalibrated. Training provenance is incomplete and the historical holdout was exposed in earlier work. Fresh labeled data is needed for an independent performance estimate; this demonstration is not approved for real retention decisions.

Implemented scope

A Qwen2.5-1.5B QLoRA configuration uses PEFT, TRL, 4-bit NF4 and LoRA rank 16. The data code includes label mapping, locality-sensitive hashing for near-duplicate removal and 80/10/10 train/validation/test splits.

Remaining evidence

Recorded training counts, reproducible training logs and base-versus-fine-tuned results are not available. A 40-example evaluation set exists, but its hand-verification is not confirmed. No improvement in JSON validity or field accuracy is claimed.
